## October 8, 2026 — M02-S03 configurable practice profiles and typed matter fields

**Slice locally complete; M02/M15/M18 remain partial.** Planned and approved in this
session (the user approved the D022 boundary as proposed). Before this slice practice
areas were a closed six-value frontend type, the Settings playbooks were fixtures, and a
matter held only a title and reference. Owners/admins can now add a practice profile,
blank or from a generic operational starter, with typed fields and publish it without
deploying code; staff pick a profile when creating a matter (or assign one later) and
fill its fields. Each matter keeps the profile version it started with.

Prerequisites: M01 live firm/session context and firm-first policy locks
(D016/D019/D020), durable matters with explicit grants (D017/D018), contacts and parties
(D021). Blueprint pages read for this slice: p13 (M02), p29 (M18), pp34–36 (practice
and jurisdiction coverage).

### Review and cleanup

- Two fresh-context adversarial migration reviews (doubt-driven, security-auditor persona)
  reproduced every finding against throwaway databases. Fixed before the API commit: a
  CHECK re-reading large values on every matter update, a database budget narrower than
  core accepted, history deletable or truncatable by the owning role, soft-deletable
  profiles breaking pinned matters, dangling current versions, NUL/surrogate text reaching
  the database and its log, required fields keyed `constructor`, reordered retries
  conflicting, description missing from audits, and rollback locking. Accepted trade-offs
  are in D022. Cross-model review was not run; it is offered to the user at close.
- `code-reviewer`: editors unmounted on matter refetch and diffed stale forms against
  refetched data (input loss, silent overwrite); a matter created without its still-loading
  profile; web prototype-key reads; starter checks blocking a committed replay. All fixed
  with browser and unit coverage. Optional items taken: recoverable name clashes, locked
  published types and reserved keys, a lighter list query, a truncation notice, focus
  return. Per-field errors in the profile editor remain a follow-up.
- `security-auditor`: no critical/high; every authorization property held end to end.
  Accepted inputs exceeding the 100 KB body limit (fixed with 90 KB budgets and a final
  413); per-firm caps and a write throttle recorded as follow-ups.
- `test-engineer`: added 32 cases (each role/grant condition alone, paging over 20 with
  ties, replay after grant/role/membership changes, restore name conflicts, races) and
  found two races, both fixed by locking first and reading joined rows separately.
- The matter detail fields and parties panels now stay mounted across refetches, like
  staff access. Test-created firms, users, profiles, matters, receipts and grants were
  removed by the suites; immutable test audit rows remain until a local reset, as before.
